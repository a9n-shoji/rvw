## PRを開く

Node.js 24.15.0以上、Git、GitHub CLI、rvwを用意します。
公開・非公開を問わず、GitHub CLIでPRを読む権限と、Gitで取得する権限が必要です。
初回はPRのマージ先（base）リポジトリをcloneして、そのディレクトリから実行します。
URL、clone先のパスは自分の対象に置き換えてください。

```bash
gh auth login
gh auth setup-git
npm install --global @a9n-shoji/rvw

gh repo clone owner/repository
cd repository
rvw doctor
rvw open https://github.com/owner/repository/pull/123
```

認証済みなら最初の2行は不要です。既存のcloneがあればcloneも不要です。
同じcloneから作ったworktreeでも使えます。forkからのPRを読む場合もbaseリポジトリを使います。
rvwはコミットを取得して読み、作業ブランチをPRのブランチへ切り替えません。

新規登録はgithub.comのOpen / Draft PRに対応します。GitHub EnterpriseとClosed / Merged PRの新規登録は未対応です。
登録後にClosed / Mergedになっても、保持したコードを表示し、GitHubと同期できます。

```bash
# 現在のブランチから初めてPRを探す
rvw open

# 登録済みPRなら、リポジトリの外からもURLで指定できる
rvw open https://github.com/owner/repository/pull/123
```

登録済みPRがそのcloneに一件だけある場合、引数なしの `rvw open` はそのPRを先に開きます。
複数PRを扱うときや、ブランチを変えた後はURLを明示すると確実です。
登録済みPRの番号だけを指定することもできますが、リポジトリ外からは全登録PRで番号が一意である必要があります。

同じ保存先を使うrvwが起動中なら、同じサーバーに別のタブを開きます。
通常は `127.0.0.1:43117` で動き、最後のタブを閉じると短い猶予の後に停止します。

## 差分から周辺コードへ進む

1. `Pull Request.md` を読み、PRが何を変えようとしているかを確かめます。
2. 左のファイル一覧で変更されたファイルを開きます。上部の **変更** で差分、**全文** で選択範囲の最後のコミット時点のファイルを読みます。
3. **対象commit** を開くと、一つのコミットを選べます。複数コミットの連続範囲は一覧をドラッグして選びます。
   **PR全体** はPR内の全コミット、**最新だけ** は最新コミットの変更を表示します。
4. **変更のないファイルも表示** をオンにして、呼び出し元、型、設定、テストなどへ進みます。
   差分のないファイルを開いても比較範囲は変わらず、**差分なし · 全文表示** と表示します。

ファイル名は左の **ファイル名を検索** で絞れます。コード中の文字列を探す場合は、エクスプローラー右上の虫眼鏡を選びます。
検索は選択コミットのリポジトリを対象にした文字列検索です。意味による検索やLSPの定義ジャンプではありません。

ファイルや検索結果を `Cmd` / `Ctrl`＋クリックすると右ペインに開けます。
開いたタブは残るので、呼び出し元と呼び出し先を並べて読めます。境界をドラッグして幅を調整し、
タブはドラッグまたはペインの **…** メニューで移動できます。ブラウザの戻る／進むで読んだ箇所へ戻れます。

リポジトリ内のMarkdownは全文表示ではPreviewが既定です。**Source** で原文へ切り替えられます。
相対リンクは同じコミットのファイルを開きます。差分表示では通常の差分を読みます。

`Pull Request.md` はGit内のファイルではなく、最後に成功したGitHub同期のタイトル・本文です。
コードのコミット選択に合わせて過去の本文へ切り替わることはありません。

## Agentに説明を依頼する

rvwで読める説明は、利用者が別に起動したAgentが、コミット済みのコードを調べて作成します。
rvwに依頼文を入力する場所や、AIを起動するボタンはありません。

Agentは同じマシン上で対象のリポジトリ、`rvw` コマンド、インストール済みSkillを使える必要があります。
ブラウザでrvwを開いたままにしておくと、CLIは通常そのrvwへのローカル接続を使います。
Agent環境のアクセス制限がある場合は、必要なローカル接続やリポジトリへのアクセスを許可してください。
別の `RVW_DATABASE_PATH` を使うときは、rvwとAgent側で同じ値を指定します。
これらにアクセスできないクラウドAgentは対象外です。

### 使うAgentのSkillを用意する

```bash
# Codexを使う場合
rvw skill install codex

# Claude Codeを使う場合
rvw skill install claude

rvw skill status
```

一回のインストールで以下の5つを配置します。内容は両Agentで共通です。

| やりたいこと                                                 | Skill                |
| ------------------------------------------------------------ | -------------------- |
| コメントを読み、調査・返信・許可された修正を行う             | `rvw`                |
| PR全体について、何を説明し何を直接読むかも含めて構成を任せる | `rvw-review-compose` |
| 一つの問いについて、コードへのリンクを持つ説明を作る・直す   | `rvw-walkthrough`    |
| 一つの問いに関係する処理やファイルを辿る図を作る・直す       | `rvw-structure`      |
| 起動後に追加されたコメント・返信を外部Agentで継続監視する    | `rvw-watch-comments` |

既定の配置先はCodexが `~/.agents/skills/`、Claude Codeが `~/.claude/skills/` 配下です。
Agentのセッションで使いたいSkillが読み込まれていることを確認します。`rvw-review-compose` を使う場合は、`rvw-walkthrough` と `rvw-structure` も必要です。
Skillが見つからない場合はAgent側で再読み込みまたは新しいセッションを開始してください。
Skillなしで依頼文だけを渡す連携はサポートしません。

rvwを更新したら `rvw skill status` でSkillの状態も確認します。旧版、ローカル編集、管理されていない差異は区別されます。
差異があるSkillは自動で上書きしません。自分の変更を確認・退避したうえで、必要な場合だけ
`rvw skill install codex --force`（または `claude`）を使います。
旧開発版の `rvw-codex` / `rvw-claude` は自動削除されないため、残っていれば内容を確認して手動で整理します。

### 一つの疑問から始める

コードへのリンクが付いた説明を **Walkthrough** と呼びます。
対象PRを先にrvwで開き、そのURLと確かめたい問いをAgentのセッションへ渡します。

```text
rvw-walkthrough Skillを使って、https://github.com/owner/repository/pull/123 の
「［確かめたい処理や条件］」を説明するWalkthroughをrvwに作成してください。
コミット済みの実装と関連するテストを調べ、説明から根拠のコードを開けるようにしてください。
確認できない点は明記してください。今回はコードの変更は不要です。
```

作成後は左の **ウォークスルー** から開けます。Agentが説明を作成・更新しても、読んでいるタブは勝手に切り替わりません。
説明内のリンクや、対応付けられた図の要素を選ぶとコードを開けます。`Cmd` / `Ctrl`＋クリックなら右ペインです。

### PR全体をどこから読むかも任せる

```text
rvw-review-compose Skillを使って、https://github.com/owner/repository/pull/123 を
理解するためのWalkthrough / Structureを、おすすめの構成でrvwに作成してください。
変更を理解するために必要な周辺コードも調べ、最初に読む入口と、説明に含めなかった範囲を教えてください。
今回はコードの変更は不要です。
```

ファイルや処理の関係を図から辿れる説明が **Structure** です。PR全体の構成では、
実在するファイルと具体的な依存関係を示す地図を必ず含みます。
ほかに何を作るかは変更内容によります。小さな変更なら地図とコードを直接読むだけの場合もあり、
WalkthroughとStructureが常に一組で作られるわけではありません。

左の **Structure** から図を開き、要素や関係を選んで根拠のコードを読みます。
要素のダブルクリックはその近傍へ、**Home** は最初の着目点へ戻ります。
**1-hop / 2-hop** で近傍を絞り、**All / Fit** で全体を確かめられます。
区分が用意された図では **Regions** から関連するまとまりを選べます。
**Export** は図全体をSVGまたはPNGで保存します。座標や表示中の範囲はAgentへ渡しません。

特定の図だけを依頼するなら、`rvw-structure Skillを使って、［PR URL］の［処理や問い］について、
関係と根拠のコードを辿れるStructureをrvwに作成してください` と伝えます。

## コメントの監視を起動する

Agent連携では、コメントする前に外部Agentの別タスクで `rvw-watch-comments` Skillを起動しておきます。
監視を続けたままrvwでコードを読み、質問を書けば、同じコメントで応答を読めます。

```text
rvw-watch-comments Skillを使って、rvwの新しいコメントと返信を監視してください。
今回は調査とrvwへの返信だけを行い、コード変更・commit・pushはしないでください。
監視を開始できたら知らせてください。
```

**監視開始の知らせを待ってからコメントしてください。** 新規に監視を始める前からあるコメントは処理せず、
全登録PRの新しいコメントと返信を扱います。監視を実行するローカルAgentのタスクと、子Agentを使える環境が必要です。
rvwだけを起動しても監視は始まりません。

コメントを受け付けると、Agentが **「🔎 確認中です…」** を投稿します。
調査が終わると、その投稿が根拠のコードへのリンクを含む回答に置き換わります。
投稿者にはCodex / Claude Codeなど監視を実行するAgent名が表示されます。
「確認中」は受付の応答で、調査完了やコメントの解決を意味しません。ほかの調査が進行中なら、受付まで待つこともあります。

新しいコメントに応答が付かない場合は、外部Agentの監視タスクが動いているか確認します。
監視開始前のコメントは、下の[一件ずつ渡す手順](#監視せずに一件ずつagentへ渡す)で依頼できます。
監視の再開に必要な情報はSkill側がリポジトリ外のローカルSQLiteに保持します。

上部の **…** で **Agentのコメントを通知** を有効にすると、初回読込後のAgentの最終回答の追加・更新をブラウザ通知で受け取れます。
ブラウザの通知許可が必要で、同じメニューから状態確認とテスト通知ができます。

## コードを確かめて質問する

説明のリンクを開いたら、表示しているコミットと強調された範囲を確認します。
Walkthroughの参照は、確実に追跡できる場合は最新コードを開きます。
対応が曖昧なら **参照時点のコード** を開き、最新と同じ位置だとは扱いません。
**最新のファイルを見る** が出る場合も、行の対応は保証されません。
Structureからは、その説明に記録したコミットのコードを開きます。
返信内のコード参照は、選択中のコミットへ対応付けられる場合はその比較で開き、対応付けられない場合は投稿時点のコードを開きます。
リンク先のコードで、説明に書かれた条件や処理を確認してください。

1. コード行にマウスを置き、行番号横の **＋** をクリックします。範囲を指定するなら、＋から必要な行までドラッグします。
2. 確認したい条件や修正してほしい内容を書き、投稿します。ファイル全体にはヘッダーのコメントボタン、
   PR全体には左のコメント欄を使えます。MarkdownのPreviewでは文章を選択して行コメントを作れます。
3. 監視中のAgentから「🔎 確認中です…」が付くのを確認します。調査後、その投稿が回答に変わります。
4. 回答と参照先のコードを読み、疑問が残れば同じコメントに返信します。納得できたら **解決** を押します。

コメントと返信はローカルに保存され、GitHubへ投稿・同期されません。
Agentを使わず、あとで自分で読むためのメモとして残すこともできます。

説明そのものが分かりにくいときは、Walkthrough全体のコメントボタンや本文の文章選択で質問できます。
`rvw-walkthrough Skillで同じWalkthroughを改善してください` とコメントすると、監視中のAgentへ届きます。
同じ説明が更新され、全体へのコメントは残ります。説明のローカル版履歴はありません。
Structure自体へのコメントは未対応なので、根拠のコードやPR全体にコメントします。

### 監視せずに一件ずつAgentへ渡す

投稿の **… → 参照をコピー** を選び、コピーした `rvw://comment/…` を依頼内容と一緒にAgentへ貼ります。
左のコメント一覧では複数件を選び、まとめてコピーできます。

```text
rvw Skillを使って、次のコメントについて調査し、rvwの同じコメントに返信してください。
確認したコードへのリンクも付けてください。今回はコードの変更やpushは不要です。

［ここにコピーした rvw://comment/… を貼る］
```

コピー内容にはSkillへの短い依頼文と `rvw://comment/…` が含まれます。そのまま貼るか、参照だけを上の依頼文へ貼ってください。
コメント参照は同じローカル保存先を読むための識別子で、公開共有URLではありません。
別の人のマシンへ参照だけを送っても、コメントは読めません。コメントはGitHubへ投稿・同期されません。

## 修正後を確認する

上の監視依頼は調査と返信だけを許可しています。コメントに修正を頼むだけでは、コード変更やpushの許可にはなりません。
継続して修正も任せる場合は、監視タスクの起動時に許可範囲を伝えてください。
監視Skillが修正・pushするのは、GitHub認証中の自分が作成したPRだけです。他人のPRや投稿者を確認できないPRは、調査と返信に限ります。

一件だけ修正を依頼するなら、コメント参照を別のAgentタスクに渡し、commitやpushまで任せるかを指定します。
以下はそのPRへのpushまで許可する例です。

```text
rvw Skillを使って、次のコメントに対応してください。
必要なコード修正、テスト、commit、対象PRのブランチへのpushまで行って構いません。
push後はrvwへ同期し、修正内容とテスト結果を根拠のコードへのリンク付きで同じコメントに返信してください。
コメントの解決は私が確認して行います。

［ここにコピーした rvw://comment/… を貼る］
```

コードを変更するのは外部Agentです。rvwは作業中のファイルを表示しないため、未コミットの修正や、
GitHubへpushしていない変更は通常のPR同期では取り込まれません。
同梱Skillで許可されたpushを行ったAgentは、続けて `rvw pr sync --stdin --json` でGitHubの状態を取り込みます。
自分でpushした場合は、rvw上部の **… → GitHubと同期** を選びます。

最新を読んでいた場合は新しいheadへ追従します。過去のコミットを選んでいた場合はその選択を保つので、
**対象commit** で確認したい範囲を選び直します。
返信、修正したコード、関連するテストを読み、納得できたコメントを **解決** にします。必要なら再度開けます。
返信を追加するだけでは未解決／解決済みは変わりません。

`Outdated` は、コードや本文の変更でコメントの位置を確実に追跡できないという表示です。
解決済みという意味ではありません。元のコメントと参照時点のコードを確認してください。
force-push前に観測したコードもGit参照で保持します。

## 保存先と外部通信を確認する

| データ・操作                                       | 扱い                                                                                  |
| -------------------------------------------------- | ------------------------------------------------------------------------------------- |
| PRタイトル・本文・状態・コミット情報               | GitHubから取得してローカルに保存。タイトルと本文は最後に成功した同期の内容            |
| コメント・返信・Walkthrough・Structure・テーマ設定 | OSのユーザーデータディレクトリのSQLiteに保存。GitHubのレビューコメントとは同期しない  |
| リポジトリの場所、参照元のコード                   | パスをSQLiteへ保存。コードはローカルGitから読み、`refs/rvw/` で観測したコミットを保持 |
| GitHub認証情報                                     | GitHub CLIが管理。rvwのDBへコピーしない                                               |
| PR本文の対応するGitHub添付画像                     | ローカルサーバーからGitHub CLI経由で取得。画像をSQLiteや永続キャッシュには保存しない  |
| ペイン配置、図の座標・表示範囲                     | ブラウザ内の一時的な閲覧状態。AgentへのCLIには含めない                                |
| Agentへ渡すコメント・コード・説明                  | 外部AgentがCLIとリポジトリから読む。そのAgentの送信先、権限、設定に従う               |

保存先は `rvw doctor --json` の `databasePath` で確認できます。
明示的に別のDBを使う場合は `RVW_DATABASE_PATH` を指定します。
既定の保存先は作成時にディレクトリ `0700`、ファイル `0600` にし、既存パスは所有者・権限を検証します。
指定した別パスの既存権限は自動変更しません。診断で警告が出た場合は確認してください。
SQLiteや `refs/rvw/` を手で編集することはサポートしません。

サーバーは `127.0.0.1` にだけ接続を受け付け、Host / Originを検証します。
PRの新規登録・同期ではGitHubへ接続します。登録済みPRを開くと、保存済みの状態を表示した後に同期を試みます。
オフラインなら保持済みのデータとGitオブジェクトを表示し、更新失敗を知らせます。

リポジトリ内の対応する画像は表示中のコミットから読みます。
PR本文では `https://github.com/user-attachments/assets/<uuid>` 形式の添付画像を取得します。
それ以外の外部画像やWalkthrough本文の外部画像は取得せず、代替表示にします。
外部リンクを自分で開いた場合は、その接続先へブラウザがアクセスします。
Agentがコードやコメントを外部へ送信するかどうかは、そのAgentの設定を確認してください。

### 表示に限界があるファイル

テキストはUTF-8を対象にし、バイナリや大きすぎるファイルは理由を表示します。
シンボリックリンクの参照先やsubmodule内を再帰的に読み込むことはしません。
対応する画像は全文または変更前後を並べて読めますが、ピクセル差分や画像座標へのコメントはありません。
サイズなどの細則は[実装仕様のファイル表示](implementation-spec.md#53-file-tree検索diff-rendering)を参照してください。
0.xの互換性と更新時の扱いは[互換性方針](compatibility.md)にまとめています。

## 起動や同期で困ったとき

```bash
rvw doctor --json
gh auth status
rvw agent status --json
```

- **新規登録や同期だけ失敗する**：GitHub認証、対象PRの権限、ネット接続を確認します。登録済みの内容は先に読めます。
- **Agentがコメントを読めない**：同じPRのローカル保存先とリポジトリを使っているか確認します。
  `rvw agent status --json` は接続先、DB、選ばれた接続方法、失敗理由を返します。
  `RVW_AGENT_SOCKET_PATH` を明示した場合は、接続に失敗しても別経路へ切り替えません。
- **pushは成功したがrvwの同期に失敗した**：pushをやり直す前に同期エラーを確認します。同期が成功するまでrvwには以前の状態が表示されます。
- **cloneの場所を変更した**：同じGitリポジトリの場所を `rvw pr attach <PR_URL> --repository /path/to/worktree --json` で登録し直します。

ブラウザを自動で開きたくない場合は次を使い、表示されたURLを手で開きます。
このコマンドは起動済みサーバーを使う場合も、Ctrl+CまでURLを使える状態に保ちます。

```bash
rvw open https://github.com/owner/repository/pull/123 --no-open
```

サーバーを端末に接続したまま通常のブラウザ起動も行う場合は `--foreground` です。
同じDBのサーバーが起動中なら競合として終了します。
ポートが使用中なら初回起動に `--port 43119` などを指定します。`--port 0` は空きポートを選びますが、
接続元のURLが変わるとブラウザの通知許可・保存設定を引き継げません。
異なるDBを同時に開く場合も別ポートが必要です。同じDBで起動中のサーバーと異なるポートを指定すると競合になります。

### 最後の復旧手段：PRをリセットする

Git参照とDBの不整合が診断された場合の正式な復旧手段です。通常の同期や更新には使いません。
まず削除される件数を確認します。

```bash
rvw pr reset https://github.com/owner/repository/pull/123 --json
```

リセットすると、そのPRのコメント、返信、Walkthrough、Structure、保持していたGit参照を削除し、
現在のGitHub状態から作り直します。**元に戻せず、バックアップや旧コメント移行も行いません。**
削除してよいと判断したときだけ、同じコマンドに `--yes` を付けて実行してください。

## デモで同じ疑問を追う

デモにはPR、コード、説明、コメントが用意されており、GitHub認証やAgentなしで操作を試せます。
Node.js 24.15.0以上、Git、pnpm 11.21.0を用意して、ソースを取得します。依存関係の初回取得にはネット接続が必要です。

```bash

```

`http://127.0.0.1:43118` に、架空の注文サービスPRを開きます。止めるときは起動した端末でCtrl+Cです。
既存のユーザーDBやSkillは使いません。デモで追加したコメントなどは再起動すると失われます。
デモは本物のrvwの画面と一時Gitリポジトリを使いますが、GitHub接続と保存APIはテスト用の仕組みです。
